# История изменений

История этого форка, от первой рабочей версии до текущей. Номера версий — этого
форка, апстрим своей нумерации не имел.

## 2026-11-08 — публикация и описание

Код с 0.5.0 не менялся, правки только в документации и примерах:

* Репозиторий опубликован: `github.com/glfenix/autofan-for-tyanS8030`; путь
  модуля Go приведён в соответствие (`make module REPO=…`).
* README: «что нужно, чтобы это заработало», обязательные переменные, два
  сценария первого запуска (`open` и `lanplus`), команды запуска и `systemctl`,
  порядок силы «флаг → окружение → файл», карта «вопрос → файл».
* docs/CONFIG.md: раздел «минимальный рабочий набор» и требования к файлу с
  паролем.
* Из примеров и `Makefile` убраны конкретные логины (`root@…`,
  `BMC_USER=fancontrol`) — остались заглушки `<user>` / `<адрес BMC>`: ни
  логинов, ни паролей в репозитории нет и быть не должно.
* Systemd unit ссылается на собственный `docs/CONFIG.md`, а не на апстрим.

## 0.5.0 — 2026-10-30

* Калибровка тахометров исправлена на `RPM = 202 + 17.2 × duty` (`RPM_OFFSET`):
  прежняя `18.5 × duty` давала ложные предупреждения на низких duty («ждёт 740,
  вентилятор крутит честные 966»).
* Тест `TestRPMCalibrationMatchesHardware` — калибровка не может разойтись с
  замерами больше чем на 10 %.
* Источник GPU без единой прочитанной температуры теперь явно сообщает ошибку, а
  не возвращает 0.
* Репозиторий приведён к публичному виду: `docs/` (железо, алгоритм, справочник
  конфига, методика настройки, результаты), `examples/` (рабочий конфиг,
  YAML, unit), `scripts/` (измерительные скрипты), `data/` (сырые замеры),
  `Makefile`, CI, `CHANGELOG`, `NOTICE`, `LICENSE`.
* Измерительные скрипты параметризованы через переменные окружения (`VM`, `PWM`,
  `TACH`, `STATE`), добавлены `calibrate-rpm.sh` (аппроксимация по точкам) и
  `summarize.py` (сводка CSV).

## 0.4.0

* **Упреждение по мощности GPU** (`G1_POWER_CURVE`, ватты вместо градусов):
  температура ядра карты не показывает нагрев корпуса, а мощность показывает.
  Итоговый duty — максимум из кривой по температурам и опережения по ваттам;
  температура остаётся старшей. Проверено на реальных вентиляторах: 250 Вт →
  60 %, 330 Вт → 75 %, 60 Вт → возврат к температурам.
* Пороги учёта источников `SRCn_FLOOR` — иначе тёплые в простое VRM/DIMM
  (46–57 °C) не давали опуститься до стартового duty.
* Учёт источников в цикле: различаются «живой, но ниже порога», «холодная
  машина» и «нет данных». Раньше первое и третье путались.
* **Ноль от источника — не температура.** Пустой hwmon-путь возвращал молчаливые
  0 °C, и контур считал это холодом, укладывая вентиляторы в минимум. Теперь
  отсутствующий путь и 0 °C — отказ (тесты `TestZeroTempCountsAsNoData`,
  `TestHwmonMissingPathReturnsError`).
* `STARTUP_DUTY` при запуске сервиса, и он **не опускает** горячее состояние:
  рестарт посреди нагрузки не укладывает вентиляторы в минимум до первого
  измерения (`TestStartupKeepsHotDuty`).
* Флаг `-v` важнее `VERBOSE=0` в конфиге (иначе отладка на хосте невозможна).
* `SRCn_SENSOR` — одна строка целиком, с аргументами команды.
* Кэш SDR на цикл: восемь BMC-источников читаются одним `ipmitool sdr elist`.
* Проверено на железе: failsafe при отказе всех источников (85 %, 1656 RPM),
  неизменение duty вниз без данных, возврат на `ON_EXIT_DUTY` при остановке,
  `systemctl reload` с битым конфигом (сервис жив).

## 0.3.0

* Модель конфигурации переехала на **несколько групп вентиляторов**: свои каналы
  ШИМ, свои источники, своя кривая, свой аварийный duty, своя калибровка.
* Основной формат конфига — внешние переменные `КЛЮЧ=ЗНАЧЕНИЕ` (`/etc/autofan/
  autofan.conf`), можно `source` в bash и переопределять из окружения; YAML
  остался как альтернативный синтаксис.
* Перечитывание конфига по `SIGHUP` (`systemctl reload`) с сохранением текущего
  duty; битый конфиг — ошибка в журнал, работа по прежнему.
* Исправлен парсер: комментарии в конце строки (`POLL_INTERVAL=25 # ...`)
  ломали разбор; поддержаны кавычки и пустые значения.
* Состояние хранится по группам, с чтением старого одногруппового формата.

## 0.2.0 — первая рабочая версия на этом BMC

* Первый рабочий контур на живом BMC: кривая, гистерезис (вверх сразу, вниз
  шагом и с выдержкой), аварийный duty, сохранение и восстановление состояния,
  проверка результата по тахометрам.
* Исправлено то, что нашлось на живом железе:
  * интерфейс `system-interface` не загружается в `ipmitool 1.8.19` → `open`;
  * байты duty отправлялись как `5a` → `ipmitool` отвергал; голое `40` читалось
    как десятичное → везде `0x%02x` + регрессионный тест;
  * команда апстрима `raw 0x2e 0x05 ...` на прошивке 6.02 → `rsp=0xc7`; рабочая
    форма `raw 0x2e 0x44 0xfd 0x19 0x00 <pwm> 0x01 <duty>`, форматы вынесены в
    профили `tyan64`/`tyan32`;
  * `qm guest exec` отдаёт `"exited": 1` (число) → жёсткий `bool` в разборе JSON
    ломал чтение GPU;
  * состояние сохранялось даже когда все записи в BMC не удались → восстанавливался
    duty, которого на самом деле нет;
  * обработчик сигналов писал в закрытый канал → остановка по systemd уходила в
    SIGKILL и вентиляторы не возвращались на `ON_EXIT_DUTY`.
* Доступ по сети (`lanplus`) с паролем из файла, не из аргументов командной строки.
* GPU из гостевой ВМ через qemu-guest-agent, `OPTIONAL` — выключенная ВМ не авария.

## О чём молчит этот changelog

Возврат в автоматический режим BMC программно не реализован: на прошивке 6.02
команда `0xff` отвечает `rsp=0xcc`. Возврат заводской кривой возможно только через
BIOS Setup (`Hardware Monitor → Smart Fan`).
