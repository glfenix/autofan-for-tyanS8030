# Публикация на GitHub

Репозиторий к публикации подготовлен (доки, примеры, скрипты, CI, LICENSE,
NOTICE), но решение «публиковать или нет» и пара деталей — за автором.

## Что решить до первого коммита

1. **Путь модуля Go.** Сейчас `module local/autofan` — чтобы форкать и собирать
   было легко, а не для публикации:
   ```bash
   make module REPO=github.com/<твой_логин>/autofan
   ```
   Все исходники в одном каталоге и в `package main`, импорта пути модуля в них
   нет, поэтому одной команды достаточно. Делай это **до** первого коммита —
   иначе потом диффом по всем файлам.
2. **Имя в `LICENSE`.** Сейчас `Copyright (c) 2026 autofan contributors`. Если
   хочешь именную охрану — замени на своё имя/ник в `LICENSE` и `NOTICE`.
3. **Насколько публичным делать `data/` и `docs/HARDWARE.md`.** Там нет ни
   паролей, ни сетевого адреса BMC, ни серийного номера — только модель платы,
   прошивка и тепловые замеры. Если и это лишнее, `git rm -r --cached data`
   перед коммитом; смысл репозитория при этом заметно уменьшится: ценность здесь
   именно в измеренных числах.
4. **Отношение к апстриму.** Он без лицензии, поэтому его код сюда не попал
   (проверка совпадений строк — в `NOTICE`). Если хочешь вежливости ради
   предупредить автора — открой issue в его репозитории со ссылкой на этот;
   формально obligation нет, идеи и набор команд BMC не охраняются авторским
   правом.

## Локальная подготовка репозитория

```bash
cd /opt/pi/autofan
git init -b main
git add -A
git status --short                 # последний взгляд: не просочилось ли лишнее
git commit -m "autofan 0.5.0: управление корпусными вентиляторами TYAN S8030"
```

Текст первого коммита, если не хочется сочинять:

```
autofan 0.5.0: плавное управление корпусными вентиляторами TYAN S8030 через IPMI

Кривая по нескольким датчикам, опережение по мощности GPU, аварийный режим
при отсутствии данных, проверка результата по тахометрам. Написано с нуля;
из апстрима взята только идея и команды BMC (см. NOTICE).

Замеры, калибровка и методика настройки — docs/RESULTS.md, docs/TUNING.md.
```

## Проверка перед push

```bash
make release-check                        # fmt + vet + тесты + сборка

# секреты: в репозитории не должно быть ни пароля, ни файла с ним
grep -rniE "password =|sshpass -e|token" --exclude-dir=.git --exclude-dir=dist --exclude=autofan --exclude=PUBLISH.md .
grep -rn "192\.168\.[0-9]" --exclude-dir=.git --exclude-dir=dist .   # приватные адреса

# серийный номер платы и другие идентификаторы твоего железа
grep -rnE "CFBF[0-9A-Z]+" --exclude-dir=.git --exclude-dir=dist .
LC_ALL=C grep -c "<твой_пароль_от_BMC>" autofan || true   # 0: пароль не должен попадать в бинарник
```

Что обязан показать последний grep по адресам: только задокументированный
пример `192.168.1.10` в комментарии к `BMC_HOST` и в примере `make deploy` —
это заглушки, не твой адрес. Всё остальное (реальный адрес BMC, логин, пароль,
серийный номер платы) в репозитории недопустимо: `examples/` уже вычищен, но
проверка перед каждым push должна быть привычкой.

## Создание репозитория

```bash
gh repo create autofan --public --description \
  'Плавное управление корпусными вентиляторами TYAN S8030 через IPMI: кривая по нескольким датчикам, упреждение по мощности GPU, безопасный отказ' \
  --source . --remote origin --push
```

Или через веб-интерфейс, затем:

```bash
git remote add origin git@github.com:<ты>/autofan.git
git push -u origin main
git tag v0.5.0 && git push --tags
```

## Оформить репозиторий

* Topics: `ipmi`, `ipmitool`, `tyan`, `s8030`, `fan-control`, `proxmox`, `golang`,
  `bmc`, `server`, `nvidia-gpu`.
* В About добавить ссылку на `docs/RESULTS.md` — это то, что отличает проект от
  «ещё одного PID-регулятора».
* Включить Issues, если готов принимать отчёты о других прошивках: таблица
  «что принимает твой BMC» (`raw 0x2e 0x05` против `0x2e 0x44`, `0xff` и т. п.)
  была бы реально полезна; формат для сбора — `docs/HARDWARE.md`.
* Если собрал релиз — прикладывать `make dist` (`dist/autofan-<версия>.tgz`):
  на серверах тулчейн Go не нужен.

## После публикации

Обновления по схеме: ветка → `make release-check` → PR → merge → `git tag`.
CI (`.github/workflows/ci.yml`) гоняет формат, `go vet`, тесты, сборку и
синтаксис скриптов — тесты не требуют железа, поэтому прогонятся на GitHub.
