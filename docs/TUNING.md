# Настройка под своё железо

Порядок шагов осознанный: сначала понять, что вообще мешается в простое, потом
кривая, потом опережение, и только потом длинная нагрузка. Пропустить первый
шаг — обычная причина «вентиляторы воют в простое».

## 0. Разведка

```bash
make
./autofan -c examples/autofan.conf --dry-run probe
```

`probe` печатает разбор конфига (группы, кривые, пороги), список датчиков BMC и
что сейчас показывает каждый источник. Ничего в BMC не пишется. Если в списке
нет нужного датчика — проверь имя по `ipmitool sdr elist`; имена на прошивках
отличаются.

Сразу стоит решить, какие каналы ШИМ регулировать. На этой плате `CPU_FAN`
(PWM 0/1) оставлен автоматике BMC: программно вернуться в автомат на прошивке
6.02 нельзя (`0xff` → `rsp=0xcc`), а забрав его себе, ты остаёшься с ручным
управлением до переустановки прошивки/сброса BIOS.

## 1. Пороги учёта (`FLOOR`) — сначала они, не кривая

Датчики VRM/памяти на серверных платах тёплые всегда: здесь `DIMM_MOSFET_1`
46–53 °C и `P0_UMC*` 52–57 °C в простое. Без порога они не позволили бы
вентиляторам опуститься до стартовых 35 %, и контур висел бы на 50–55 % круглые
сутки.

Сними простой (машина работает как обычно, без тестовой нагрузки) 10–15 минут:

```bash
python3 scripts/thermal-sample.py 900 > idle.csv
python3 scripts/summarize.py idle.csv
```

И поставь `FLOOR` примерно на 2–3 °C выше максимумов простоя. Пример соответствия
по этим замерам: `air_outlet 37`, `air_inlet 42`, `cpu_mosfet 54`,
`dimm_mosfet 56`, `soc_mosfet 50`, `dimm_channels 58`, `nvme 50`.

Признак, что угадал: в журнале цикла появляется `ещё N холодных, 0 недоступных`,
а duty опускается до `STARTUP_DUTY`. Признак, что перегнул: датчик, который
должен реагировать, перестаёт влиять (duty не растёт под нагрузкой) — верни
порог на пару градусов ниже.

Порог — не «фильтр датчика», а часть модели: он говорит, с какого градуса этот
источник начинает представлять интерес.

## 2. Кривая по температурам

Опирайся на тест ступеней, а не на ощущения:

```bash
# включи постоянную нагрузку (инференс, рендер, что угодно реалистичного)
sudo DUTIES="35 45 55 70" ./scripts/dutytest.sh 180
```

Скрипт по очереди ставит ступени (по 3 минуты), остановив сервис, и печатает
датчики. Смотри на те сенсоры, которые реально должны охлаждаться корпусным
потоком: зона VRM, память, выхлоп, NVMe. Точка, дальше которые рост оборотов
перестаёт давать эффект, и есть смысл кривой. Ставить 70 % там, где 55 % даёт
те же 55 °C, — просто шум.

Форма кривой для этой машины:

```
G1_CURVE=45:35 50:45 60:55 70:70 78:85 85:100
G1_CURVE_MODE=step
```

`step` предпочтителен: он не гоняет duty из-за каждого градуса. Точки ниже первой
действуют как `MIN_DUTY`; проверка конфига не пустит точку за пределы
`MIN_DUTY..MAX_DUTY`.

## 3. Опереждение по ваттам GPU

Нужно, если карта греет зону, где стоят твои датчики, а сама остаётся холодной
(у нас выхлоп шёл вверх, на кулер CPU и зону VRM/памяти). Проверить просто: при
нагрузке на карту смотри, растут ли `P0_UMC*` / `CPU_MOSFET` / `SYS_Air_Outlet`,
оставаясь при этом ниже `FLOOR`. Если да — температуры тебе вообще не расскажут
о нагреве, и без ватты контур будет спать.

Старт: `80:40 150:50 220:60 300:75`, то есть чуть выше порога, где карта начинает
греть корпус. Верх кривой стоит измерять длинной нагрузкой 250–300 Вт (см.
«Чего не измерено» в `docs/RESULTS.md`) — до этого это разумное предположение.

Отключается пустой строкой `G1_POWER_CURVE=`.

## 4. Тахометры

```bash
sudo ./scripts/calibrate-rpm.sh          # сервис остановит и вернёт обратно
```

В конце печатает `RPM_PER_DUTY` и `RPM_OFFSET` по методу наименьших квадратов и
расхождение по точкам. Ставь эти два числа в конфиг. Смещение обязательно: если
подгонять только наклон, линия не проходит через реальные точки внизу диапазона,
и проверка результата начинает сообщать о «слишком быстрых» вентиляторах на
низких duty (на этой плате первая калибровка `18.5 × duty` именно так и
ошибалась: ждала 740 RPM, а было честные 966).

`RPM_WARN_FACTOR` оставь 0.25–0.35: меньше — ложные срабатывания от разброса
самих вентиляторов, больше — мёртвый подшипник не заметишь.

## 5. Гистерезис и опрос

* `POLL_INTERVAL` 20–25 с (по сети 30–40 с): SDR обновляется раз в 1–2 с, корпус
  нагревается десятками секунд, чаще — просто лишние запросы к BMC.
* `STEP` 4–5 % и `DWELL` 90–120 с: вниз медленно, вверх немедленно.
* Подъём вверх намеренно без выдержки — задержка в сторону недоохлаждения.

Проверка на дребезг: `scripts/summarize.py` печатает число смен duty в ряду.
Много смен при малом разбросе температур — подними `STEP`/`DWELL` или опустись
`FLOOR`-пороги (часто дребезг даёт источник, болтающийся вокруг своего порога).

## 6. Проверка аварийных режимов (делай это до ввода в постоянную эксплуатацию)

Проще всего временно перевести все источники на несуществующие hwmon-пути:

```bash
sed 's/^SRC\([0-9]*\)_TYPE=.*/SRC\1_TYPE=hwmon/; s#^SRC\([0-9]*\)_SENSOR=.*#SRC\1_PATH=/sys/class/hwmon/none/temp1_input#' \
    /etc/autofan/autofan.conf > /tmp/bad.conf
systemctl stop autofan
/usr/local/sbin/autofan -v -c /tmp/bad.conf once     # ждём FAILSAFE 85%
/usr/local/sbin/autofan -c /etc/autofan/autofan.conf restore
systemctl start autofan
```

Ожидаем: `нет данных от источников ... -> FAILSAFE 85%`, тахометры подтверждают
высокие обороты. Ровно это отличает безопасный контур от «нет данных = холодно».

Полезно так же проверить:

* `systemctl stop autofan` → возврат на `ON_EXIT_DUTY`;
* `systemctl reload autofan` с заведомо битой строкой в конфиге → сервис остаётся
  `active`, в журнале `конфиг не перечитан`;
* записать в `state.json` высокий duty и перезапустить сервис → стартовое значение
  не опустит вентиляторы до первого измерения.

## 7. Типовые ошибки

| ошибка | чем кончается |
|---|---|
| нагрузка запускается внутри ВМ | 24 vCPU из 48 = половина машины; замеры кажутся оптимистичными |
| нет `FLOOR` у VRM/DIMM | 50–55 % в простое, вечный шум |
| ориентация на температуру ядра GPU | карта 42–53 °C при 110–300 Вт: сигнал отсутствует |
| ноль считается температурой | мёртвый/не существующий датчик укладывает вентиляторы в минимум |
| наклон калибровки без смещения | ложные предупреждения тахометров на низких duty |
| попытка вернуть автоматику BMC (`0xff`) | `rsp=0xcc`; и канал остаётся ручным |
| байты duty без `0x` | `ipmitool` читает `40` как сорок, а `5a` отвергает |
| слишком малый `MIN_DUTY` | после падения BMC вентиляторы останутся на минимум |
| `SIGKILL` вместо `stop` | `ON_EXIT_DUTY` не выполняется — нужен `SIGTERM` |

## 8. После изменений в шасси

Приедут райзеры / переставишь вентиляторы / поменяется маршрут воздуха — заново
пройди шаги 1, 2 и 4: пороги простоя, ступени нагрузки, калибровка тахометров.
Сама логика при этом не меняется: `FLOOR` и кривые — это модель твоего
шасси, а не кода.
